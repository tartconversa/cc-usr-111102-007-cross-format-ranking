# 跨业态推荐：离线评估摘要

所有数值来自合成资料，是离线估计，不是线上因果收益证明。

## 数据与切分
- 原始曝光行 32，去重后请求 32，移除重复行 0
- train: 20 个请求
- validation: 6 个请求
- test: 6 个请求

## 记录策略核验与手算校验
- 记录策略与候选集均匀一致: True（偏离 0 条）
- IPS=0.250000（期望 0.25，通过=True）；SNIPS=0.333333（期望 1/3，通过=True）
- IPS/SNIPS 在 policies 给出的目标被记录动作概率下计算。其余候选动作的目标质量未逐项规定，但记录策略在候选集上均匀已核验，其 μ 为正；因此这可读作该候选集内目标的离线估计。

## 时间穿越检查
- 切分重叠: 无；同请求跨集合: False
- 属性版本违规: 0 条；时间顺序: True；结论: 通过
- 反事实: 按最新版本会把 f 误判为闭店并排除；as-of 版本仍营业。

## 不可支持策略与支持损失
- 状态: proven_zero_support；完整策略价值可识别=False
- 可证明零支持请求: 32 个，零支持质量合计 32.000
- 目标在日志零支持动作上有正概率：这部分价值不可识别。表中 IPS/SNIPS 只是已识别部分，禁止当作完整策略收益。
- 对照（候选集均匀随机目标）: verified_full_support，完整价值可识别=True

## 排序器对比（预测质量 vs 策略价值）
- 加权对数损失：基线 0.261375，学习排序器 0.131114
- MRR：基线 0.408，排序器 0.408；排第一比例 基线 16.7%，排序器 16.7%
- 预测排序更好的排序器，其目标列表在日志中的回报估计也可能更高；但两者是不同问题：日志选中项目本身受记录策略影响，排序指标高不代表线上因果收益。

## 约束重排与动作概率
- 无法填满演示：请求长度 3，可用 3 个，最终 2 个
  - 原因：同业态上限 2：{'dining': 3}，最多可填 2 项
- 重排前概率反例：6 个请求中，重排前分数与真实抽取概率不同；不能冒充动作概率
- exact_enumeration: 请求 6，枚举 84，抽样 0，最大蒙特卡洛标准误 0
- 枚举成本 ≈ 合法列表数 × 列表长度；抽样成本 ≈ 样本数 / 接受率 × 列表长度。合法列表数由按业态分组的 DP 先算出，超过预算才转为拒绝采样。

## 属性版本切换与冷启动
- f 在 2026-10-20 前 open=True，之后 open=False
- 冷启动项目基线分数=0.636364，若违规回填未来热门度会变成 0.894831

## 声明
- 日志是观察性的；所有 OPE 数值都依赖记录策略与目标概率的给定假设，不是线上因果收益的证明。
- 目标动作概率同时包含重排列表概率与最终均匀抽取，不能使用重排前分数。
- 支持损失存在时只报告已识别部分，拒绝称完整策略收益。
- 裁剪后的 IPS 是有偏估计量，与未裁剪结果分列，不标注为无偏。
- 冷启动项目使用中性先验，不使用未来点击或热门度回填。
